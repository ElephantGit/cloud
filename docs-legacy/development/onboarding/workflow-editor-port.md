## 第 2 页 —— 为什么这不是「复制粘贴」

**这页在讲什么：** 管理预期。先讲清工作量，后面讲进度才有参照。

| 要搬的东西 | 行数 |
| --- | --- |
| 工作流编辑器（33 个文件） | ~15,000（测试另 ~8,400） |
| 运行查看器 | ~14,400 |
| 运行时纯逻辑 | ~4,400 |
| 数据层 / 契约 | ~2,800 |
| **合计** | **~34,000 行** |

- 两个代码库技术选型不同，不能直接复制文件
- desktop 最大单文件 2,853 行，Cloud 规则是**单文件 ≤800 行** —— 每个大文件都要按职责拆开
- **结论**：跨仓库的移植工程，只能分阶段交付

## 第 3 页 —— 关键决策与必须的适配

**这页在讲什么：** 把「为什么这么做」讲清楚，避免后面反复讨论。

### 五个已拍板的决策

| 决策点 | 选择 |
| --- | --- |
| 数据存哪 | 真后端持久化（PostgreSQL + Go），不做前端假数据 |
| 和 `@` 提及的关系 | 打通 —— `@` 出来的就是用户自己建的工作流 |
| 移植多少 | 完整移植（10 种节点 + 版本发布 + 导入导出 + 撤销重做） |
| 运行查看器 | 一起搬 |
| 界面语言 | 保留中英双语 |

### 四个绕不开的适配

| 适配项 | 怎么办 | 为什么 |
| --- | --- | --- |
| 状态管理 | zustand → React 原生 state | Cloud 因 zustand 弄坏过三次锁文件，已刻意移除 |
| UI 组件库 | desktop 的 → Cloud 的 shadcn | 两套并存会样式打架、触发重复代码检测 |
| 文件大小 | 拆到 800 行以下 | lint 硬性要求 |
| 测试 | 搬来的代码必须自带测试 | 覆盖率要求 ≥80%，且有「8 行雷同即失败」检测 |

> 幸运：两边底层都用 `@base-ui/react`，表单控件可 1:1 移植。

## 第 5 页 —— 已完成：地基（阶段 0–2）

**这页在讲什么：** 三个地基阶段，每个一句话说清在做什么。

**阶段 0｜先验最危险的不确定性**
担心 React 19 / Vite 8 这些新技术跟画布库不兼容 —— 若不兼容后面全要推倒。先装依赖 + 渲染静态画布验证。**结果：通过。**

**阶段 1｜把不依赖界面的「大脑」先搬完**
节点数据长什么样、图怎么存 JSON、能不能连线、变量有哪些类型 —— 14 个模块、12 个测试文件 117 条用例。最容易搬、复用率最高。

**阶段 2｜先有真数据库，界面才有东西可存**
建 `workflows` 表 + 5 个接口。遵循项目硬性规矩：**每查询带租户 ID**（公司间数据隔离）、**改必须带版本号**（防两人同时改互相覆盖）、**删除是软删除**。真 HTTP + 真数据库集成测试通过。

## 第 6 页 —— 已完成：能用（阶段 3–5）

**这页在讲什么：** 三个让功能真正对用户有用的阶段。

**阶段 3｜第一次用户能看见**
侧边栏出现「工作流」；列表页有搜索 / 新建 / 空状态；只读详情页；中英双语框架（60 条文案 × 2 语言）+ 语言切换。

**阶段 4｜工作流真正可编辑**
开始 / 智能体 / 输出三种节点，能拖、能连线、能改配置。**自动保存**：连续快速编辑合并成一次请求、失败自动重试 3 次、关页面时补存未落盘的。未实现的节点类型明确显示「后续版本提供」，不让用户以为坏了。

**阶段 5｜把两个功能缝起来（关键一步）**
之前 `@` 出来的是**写死在代码里的两个假数据**，现在是自己建的工作流。工作流「开始」节点的输入变量**自动变成** `@` 之后的表单字段（桌面版 8 种控件 Cloud 只支持 6 种 → 降级不丢弃）。这个阶段没改接口契约，说明接缝设计对了。

## 第 7 页 —— 进行中：阶段 6（约 10%）

**这页在讲什么：** 讲当前正在做的、也是最难的一块。

**目标**：补齐剩下 7 种节点 —— 条件 / 工具 / 交汇 / 人工审批 / 循环 / 迭代 / 子流程，每种都要有配置表单。

## 第 9 页 —— 质量怎么保证（门禁）

**这页在讲什么：** 解释「门禁」这个词，以及为什么它重要。

> 「门禁」= 一套自动检查脚本，像大楼闸机，代码想留下就得全部刷过去。

**前端 9 道**：格式 → 静态检查（含单文件 ≤800 行、单函数 ≤100 行）→ 类型 → 测试（**覆盖率 ≥80%**）→ 模块边界 → 注释 → 死代码 → 重复代码（**8 行雷同即失败**）→ 构建

**后端 5 道**：编译、单元测试、Go lint、契约生成、真数据库集成测试

**为什么重要**：搬 34,000 行风险很高，这些检查抓的是肉眼看不出的东西 ——「你这新文件和另一个文件太像了」「这导出没人用，你可能白搬了」。

**已知在这台机器上失效的（主动交代）**：

- Go 格式检查**完全不可用** —— Windows 换行符问题导致 94 个正常文件被误报；**绝不能为让它变绿去跑格式化命令**，会把整个库改一遍
- 协议检查、竞态检测测试 —— 缺工具，不可用
- 一个文件权限测试 —— Windows 没有 POSIX 权限概念，注定失败
