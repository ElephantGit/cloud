# 协作

页面和导航叫「协作」（路由 `/collaboration`），领域概念仍是「小队」（squad）。小队是工作区内人和 Agent 的协作编组：回答「哪些人和 Agent 一起承接哪类任务」，与工作区成员资格分开。页面展示真实的小队列表与详情，数据来自 v2-server 的小队接口。

## 已经有的

- 列表显示服务端返回的有效计数：人类成员数、Agent 成员数、维护者数，以及是否已设 leader。空态引导创建一个小队，不展示演示卡片。
- 详情按类型展示成员（人类 / Agent 分色）、各自职责、维护者与 leader 标记，并列出已退出的历史编组。
- 创建小队时创建者成为本队人类维护者；维护者可以编辑名称、简介与协作说明，或归档。归档需要二次确认，归档后详情只读。
- 维护者可以从「添加成员」面板加入已有工作区成员：候选只来自契约的 `tenants/{tid}/members`，已在本队的有效成员不再出现，可按姓名筛选并填写职责。移除成员需要二次确认，移除后进入「已退出」历史，界面上写明移出小队不影响工作区成员资格。
- 同一个面板还能加入空间里已安装的 Space Agent：候选来自契约的 `spaces/{sid}/plugins`，只列 `kind=agent` 且观测为已安装的条目，显示插件标识与版本，不虚构 Agent。加入只建立本队编组，不启动执行，也不授予运行时权限；Agent 不能是维护者。
- 写操作按小队 version 做乐观校验；版本过期、无权限或小队已归档时给出对应提示，不静默吞掉。

## 还没有的

- 多用户登录与邀请：现在只有开发登录的单个演示用户。
- 成员自己退出、维护者交接、leader 设置。
- 任务协作视图、`@小队` 与指派；任务与真实执行仍属后续工作。
- 自动委派与 leader 路由。界面明确写「尚未接入」，不提供暗示可用的入口。

小队成员关系本身不授予私人模型、Git 凭据或运行时权限。

## 接口与检查

小队接口不在正式 Cloud 契约里，由 `v2-server/squads.openapi.json` 描述，用 `npm run api:generate:squads` 生成 `api/generated.ts`；`npm run check` 会先做 `api:check:squads`，确认生成结果没有漂移。会话与租户继续走正式生成客户端。

`npm run check` 运行类型检查、lint、单元测试和构建；`npm run e2e` 用真实 v2-server 与 PostgreSQL 跑建队、刷新、归档流程，并通过 `E2E_DATABASE_URL` 与 `PW_CHROMIUM_PATH` 指定数据库和浏览器。
