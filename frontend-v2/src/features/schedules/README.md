# 定时任务交互原型

本目录是用于讨论界面结构的可丢弃原型，不是真实调度功能。保留在演示分支，选定设计后再实现正式的数据接入。

## 预览

在 `frontend-v2` 目录运行 `npm run dev -- --port 5188`，打开 `/schedules?variant=A`。需要现有 v2-server（默认 8090）提供登录。

- A：任务列表与右侧配置／详情抽屉。
- B：任务列表与常驻详情工作台。
- C：任务卡片与三步创建向导。

开发环境显示底部切换条，可切换布局或确认重置样例；未聚焦表单控件时也可用左右方向键切换。刷新恢复四个样例。详情中的“运行记录 → 演示选项”可以模拟失败。

## 行为边界

所有定时任务、项目、工作流和输出均为模拟数据，存于本目录的 zustand store。不会调用任务 API、AI 或真实调度器；只有应用外壳仍使用真实登录接口。

直接对话每次建立独立的模拟对话，项目可选；工作流必须选项目、已发布版本与必填参数。工作流版本固定，输入与项目名称在模拟运行时快照保存。暂停不会删除历史，手动模拟不会恢复启用；正在模拟的同一任务不会重复启动。

日历规则按所选时区的本地时间计算；夏令时不存在的时刻跳过。小时规则从创建时间起按固定时长计算。原型时区选择覆盖北京、东京、伦敦、纽约和 UTC。

模型、项目、工作流版本、任务配置和运行记录均为前端内部类型，不能直接视作 Cloud 请求。正式 ScheduledTask 契约的 issueId/agentId 模型还不能表达本原型的两种目标。

## 验证

`npm run check` 验证类型、lint、单元行为与构建。

`npm run e2e -- --config=src/features/schedules/prototype.playwright.config.ts` 在独立端口 18870/18871 上运行原有外壳测试及原型闭环测试，使用已有 PostgreSQL e2e 数据库。需要 Playwright Chromium；也可通过 `PW_CHROMIUM_PATH` 指向本机 Chromium 浏览器。
