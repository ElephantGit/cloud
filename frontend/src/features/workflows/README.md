# 工作流页面与契约接线

本模块组合工作流列表、编辑与运行页面，维护 API 查询和功能级翻译；图的纯规则属于 `runtime/`，画布与检查器属于 `editor/`，运行展示属于 `run/`。

| 文件                          | 职责                           |
| ----------------------------- | ------------------------------ |
| `api.ts`、`error-messages.ts` | 查询、变更和稳定错误映射       |
| `*-page.tsx`                  | 路由页面组合                   |
| `*translations.ts`            | 功能文案与发布门禁的本地化指导 |

依赖生成 API、基础组件、身份与空间上下文；应用路由消费本模块。发布错误按稳定门禁码显示具体、可操作的原因，不展示原始服务端消息。测试通过查询边界和页面行为验证契约，不能用通用提示掩盖已知门禁原因。
编辑页离开前等待草稿保存；失败时保留画布并让作者选择留下或放弃修改后离开，不能反复自动重试而困住导航。
运行页按轮展示 Loop 与 Iteration：`run/run-rounds.ts` 是把 `node_states` 里的轮次文档（归档 + 顶层活动轮）投影成轮次的唯一入口，最后一轮只出现一次，未执行的成员显示为未到达；成功 Loop 的轮次文档里有 `reason`（`condition_satisfied` / `max_iterations` / `loop_exit`）就直接用；没有时只按已提交事实推断，到达上限且策略为 succeed 时只显示「已完成」。
Agent 节点在检查器里通过 `useWorkflowNodeSession` 读取会话记录：分页固定在同一次尝试上，并用响应返回的 `nextBefore` 继续向前翻页，重试不会把另一次尝试的记录拼进来。`run/run-node-session-view.ts` 把已加载的页按从早到晚投影（节点回显的用户输入单独成行，Node 自己报的 `gap` 单独成行标出记录缺失的位置，而不是显示成原始 JSON），并给出服务端能证明的读取状态、逐页的完整性提示，以及只在节点状态描述本次尝试时才显示的结束原因；没有记录的状态（`not_started` / `awaiting_first_record` / `unavailable` / `unknown`）显示对应说明，而不是画成空会话；结束原因也不充当输出。
