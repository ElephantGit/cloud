# 动态表单

`workflowforms` 只校验冻结配置、问题身份和答案，不创建任务。工作流 `form` 节点读取已发布快照的配置和上游变量，将报告及问题冻结到 PostgreSQL；`createTasks` 是独立的后续节点。

首期每张根图一处表单。表单后只允许创建任务及输出，不支持容器中的表单或提交后继续 Agent。字段支持只读、文本、多行文本和下拉；确认结果与负责人是固定的逐行控制项。问题最多 100 行，稳定 `key` 必须非空且唯一。上游应按检查项和对象生成 key，不使用日期或随机标题。

读取、草稿、提交分别使用 `GET`、`PUT`、`POST /api/v2/tenants/{tid}/workflow-runs/{rid}/form`。草稿要求当前 `version`；提交还要求 `Idempotency-Key`。服务端按当前成员身份和冻结确认人授权，管理员可提交。答案只能引用现有问题，不能改写来源证据。最终答案、提交者、时间、节点完成和变量池在同一事务中保存。重复提交返回已接受结果。

创建任务按租户、项目和问题 key 锁定关联槽，复用 `pending/running/review` 任务且不转派它；已完成或取消的任务允许下次新建。任务、问题关联、批次回执与 createTasks 节点完成同事务提交。负责人仍按现有任务规则检查；分派不会自动启动 Agent。任务描述保存报告入口，完整证据留在表单。

等待的表单和已提交的确定性后续步骤可以恢复，普通执行中的 Agent 仍按既有规则中断，不重放。取消与提交使用同一运行锁。`POST …/form/retry` 仅重试失败的任务创建节点，不能复活取消的运行或重跑巡检。

定时轮次的 `waitingForInput` 表示该轮已进入无需 Agent 执行的人工处理阶段。它仍未结束、仍被跟踪，但不占用同计划下一次自动执行的位置。`released` 保留原来的终态收尾含义。

DTS 不在后端执行。前端 demo adapter 只生成模拟回执，不能改变真实任务或工作流结果。
